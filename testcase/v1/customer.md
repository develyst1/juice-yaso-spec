### TC-CUS-01-01 สั่งสำเร็จ
**เงื่อนไขก่อน:** ไม่มี session login  
**ขั้นตอน:** เปิดหน้าแรก → เลือกลัง/จำนวน → เลือกรส → กรอกชื่อ+เบอร์ → ตรวจยอดสินค้า+มัดจำ → ยืนยัน  
**คาดหวัง:** ได้บัตรคิว; สถานะ = `awaiting_payment` / รอชำระ; ไม่ต้อง login

### TC-CUS-01-02 ไม่เลือกลัง
**คาดหวัง:** สร้างออเดอร์ไม่ได้; ไม่ได้บัตรคิว

### TC-CUS-01-03 ไม่กรอกชื่อหรือเบอร์
**ขั้นตอน:** เลือกลังครบแต่เว้นชื่อหรือเบอร์ว่าง → ยืนยัน  
**คาดหวัง:** สร้างออเดอร์ไม่ได้ (บังคับชื่อ+เบอร์ก่อนชำระ/ก่อนได้บัตรคิวตามสัญญา)

### TC-CUS-01-04 หลายขนาดลัง
**ข้อมูล:** 30×1 + 50×1  
**คาดหวัง:** แก้วรวม = 80; มัดจำ = 50+90 = 140; หลาย OrderLine

### TC-CUS-01-05 ปนหลายรส
**ขั้นตอน:** สั่งหลายบรรทัด/หลายรส (เช่น ส้ม + องุ่น) ในออเดอร์เดียว  
**คาดหวัง:** บันทึกรสครบตามที่เลือก; ไม่บังคับรสเดียว

### TC-CUS-01-06 แคตตาล็อกรส
**คาดหวัง:** มี ส้ม องุ่น โกโก้ ลิ้นจี่ บลูเบอร์รี่; สีหลักแบรนด์ส้ม

### TC-CUS-02-01 ราคาฐาน
**ข้อมูล:** แก้วรวม ≤100 (เช่น 50×2 = 100)  
**คาดหวัง:** ราคา/แก้ว = 5; ยอดสินค้า = แก้ว × 5

### TC-CUS-02-02 ส่วนลด bulk
**ข้อมูล:** แก้วรวม >100 (เช่น 100×2 = 200)  
**คาดหวัง:** ใช้ 4.5 ทั้งออเดอร์; ไม่คิดขั้นบันได

### TC-CUS-02-03 ขอบ = 100
**คาดหวัง:** ยังใช้ 5 (เงื่อนไขคือ **>** 100)

### TC-CUS-02-04 ขอบ >100
**คาดหวัง:** เมื่อแก้วรวม >100 ใช้ 4.5 ทั้งออเดอร์ (สูตรจากแก้วรวมตามขนาดลังที่ล็อก)

### TC-CUS-03-01 มัดจำตาราง
| ขนาด | มัดจำ/ลัง |
|------|-----------|
| 30 | 50 |
| 50 | 90 |
| 60 | 90 |
| 100 | 150 |
**คาดหวัง:** ตรงตาราง; แยกจากราคาน้ำบนสรุป

### TC-CUS-03-02 มัดจำหลายลัง
**ข้อมูล:** 30×2 + 100×1 → มัดจำ = 250  
**คาดหวัง:** รวมถูกต้อง ไม่ปนยอดสินค้า

### TC-CUS-04-01 / 02 บัตรคิว
**คาดหวัง:** รหัสสาธารณะผูกออเดอร์; สถานะเริ่ม `awaiting_payment`; เปิดด้วยรหัสโดยไม่ login ได้

### TC-CUS-05-01 ชำระ + อัปสลิป
**ขั้นตอน:** เปิดบัตรคิว → เห็น QR และ/หรือเลขบัญชี+ชื่อธนาคารจาก config → อัปสลิป  
**คาดหวัง:** สถานะ → `awaiting_slip_review`; สลิปเข้าคิวแอดมิน

### TC-CUS-05-02 ไม่มีไฟล์สลิป
**คาดหวัง:** อัปไม่สำเร็จ; สถานะไม่เปลี่ยนเป็นรอตรวจสลิป

### TC-CUS-05b-01 อัปสลิปใหม่หลังปฏิเสธ
**เงื่อนไขก่อน:** สถานะ `slip_rejected` มีเหตุผล  
**ขั้นตอน:** อัปไฟล์สลิปใหม่จากบัตรคิว  
**คาดหวัง:** สถานะ → `awaiting_slip_review`; ทำซ้ำได้จนกว่า approve หรือยกเลิก

### TC-CUS-05b-02 แสดงเหตุผลปฏิเสธ
**คาดหวัง:** เหตุผล reject เห็นบนบัตรคิว

### TC-CUS-06-01 track
**คาดหวัง:** เห็นสถานะปัจจุบันตาม enum ที่ล็อก โดยไม่ login

### TC-CUS-06-02 รหัสผิด
**คาดหวัง:** ไม่แสดงออเดอร์ของคนอื่น

### TC-CUS-06-03 ไม่มีดูออเดอร์เก่า
**คาดหวัง:** v1 ไม่มีฟีเจอร์ลิสต์ออเดอร์เก่าโดยไม่มีรหัสบัตรคิว

### TC-CUS-07-01 ยกเลิกตอนรอชำระ
**คาดหวัง:** สถานะ → `cancelled`; ไม่มีเงินเข้า → ไม่ต้องคืนอัตโนมัติ

### TC-CUS-07-02 ยกเลิกตอนอยู่ในคิว
**เงื่อนไขก่อน:** สลิปอนุมัติแล้ว สถานะ `in_queue`  
**คาดหวัง:** ยกเลิกได้; เงินคืนด้วยมือโดยแอดมิน (v1 ไม่มี auto-refund)

### TC-CUS-07-03 ยกเลิกหลังเริ่มแพ็ค
**เงื่อนไขก่อน:** สถานะ `packing` หรือ `ready_for_pickup` หรือ `picked_up`  
**คาดหวัง:** ยกเลิกไม่ได้
